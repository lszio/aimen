# 用户体验指南

## 界面区域构成

一个能力应该落在哪个界面区域、用户应该从哪里触发它、哪一类区域更适合当前任务。

### 主要区域

| 区域 | 适合放置 |
|------|----------|
| **菜单栏** | 稳定、可归类的全局入口，例如插件总入口、帮助入口、工作区级动作 |
| **侧边栏** | 长期存在的导航型内容、对象结构以及辅助信息，例如项目树、属性面板 |
| **工作区域** | 核心任务编辑页、配置页、专用工作页面；侧边栏和菜单不够用时才占工作区域 |
| **巡视窗口**（下方） | 过程信息、日志、输出、问题列表、阶段性反馈 |
| **状态栏**（底部） | 轻量状态和轻量动作，避免把状态栏当主功能承载区域 |

![IDE 总体区域图](./images/framework.png)

### 常见入口类型

| 入口类型 | 适合用途 |
|----------|----------|
| **上下文菜单** | 只对当前对象或当前节点有效的局部动作 |
| **Webview** | 复杂界面、富表单、可视化结果和结构化详情页 |

## 选择建议

- 功能是**上下文局部动作** → 菜单栏、上下文菜单或页面内部入口
- 功能是**长期展示结构化内容** → 侧边栏、视图、巡视窗口
- 功能是**完整页面或编辑体验** → 工作区域
- 功能是**复杂界面、富表单、可视化结果** → Webview

## 限制

- **没有 DOM 访问**：插件无权访问 Baosky UI 的 DOM，不能编写自定义 CSS 应用到 Baosky 或向 UI 添加 HTML 元素
- **没有自定义样式表**：用户或插件提供的自定义样式表会与 DOM 结构和类名冲突，Baosky 通过精心设计的插件 API 提供自定义支持
